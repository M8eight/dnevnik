# ADR 05: Предгенерация lesson_instances на горизонт текущего учебного периода

## Статус
Accepted

## Контекст
lesson_instances — конкретные экземпляры уроков на дату, порождаемые из
шаблона расписания (schedule_lessons). От способа их создания зависит
производительность сборки дневника/журнала и возможность кэширования.
Отдельный вопрос — горизонт генерации: слишком короткий даёт риск пустого
дневника при сбое cron, слишком длинный — избыточная генерация того, что
может измениться.

## Рассмотренные варианты
- **On-the-fly расчёт дат** без хранения строк — отклонён: больше CPU-
  нагрузки на каждый запрос, нечего кэшировать как стабильную сущность,
  менее наглядный join оценок/посещаемости.
- **Фиксированный rolling-горизонт** (например 2-3 недели вперёд) — проще,
  но произвольная константа и риск рассинхронизации на границах окна.
- **Горизонт = граница учебного периода** — материализация строк заранее,
  осмысленная доменная граница вместо произвольного числа.

## Решение
Материализация lesson_instances двумя механизмами:
- **точечно** — при создании schedule_lesson сразу генерируются instances
  вперёд для него;
- **массово по cron** — на весь текущий academic_period для всех активных
  расписаний класса.

Изменения расписания (close/create) не ждут cron: будущие пустые instances
после даты закрытия удаляются, а instances с уже привязанными данными
(оценки/посещаемость/дз) не трогаются никогда — история дневника не
меняется задним числом.

## Последствия
+ Дневник/журнал строятся как обычные join к материализованным строкам —
  просто, предсказуемо, легко кэшируется.
+ Горизонт совпадает с доменной границей (период), а не произвольной
  константой.
+ Изменения расписания обрабатываются немедленно, без потери истории.
− Массовая генерация по cron (load()) не сбрасывает кэш
  schedulesByStudentId — при прогретом кэше данные могут быть неактуальны
  до TTL. Нужен @CacheEvict в load() либо пересмотр TTL.
− Длинный период -> заметный объём строк генерируется заранее; на текущем
  масштабе не проблема, при расширении на несколько школ — пересмотреть.
